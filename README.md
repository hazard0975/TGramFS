# Telegram WebDAV & Virtual Network Drive Service

Универсальный фоновый сервис (C# / .NET) для работы с файловым хранилищем и медиатекой в Telegram через протокол **WebDAV** с возможностью автомонтирования **настраиваемого виртуального сетевого диска** (например, `T:`, `Z:` или любого свободного).

Предыдущая версия спецификации (узконаправленный плагин AIMP) сохранена в файле: [`README_V1_AIMP_PLUGIN.md`](./README_V1_AIMP_PLUGIN.md).

---

## 📌 Концепция и цель проекта

Создание единого автономного сервиса, который полностью превращает Telegram-аккаунт в локальное облачное диск-хранилище и медиасервер, полностью закрывая задачи загрузки, организации, версионирования, удаления и воспроизведения файлов.

Сервис предоставляет универсальную WebDAV-точку доступа (порт настраивается, по умолчанию `http://localhost:37000/`) и автомонтирование настраиваемого виртуального диска в Windows (на выбор: нативный драйвер **WinFsp** с прямым чтением в ОЗУ без дискового кэша или **WebDAV**).

### Ключевые преимущества:
1. **Поддержка двух движков диска (WinFsp & WebDAV)**:
   * **WinFsp (рекомендуется)**: Нативный драйвер файловой системы Windows. Исключает проблемы службы WebClient, не требует патчей реестра, не создает временных файлов в `Tfs_DAV` на системном диске C: и отдает чанки Telegram напрямую в память AIMP / Проводника.
   * **WebDAV**: Резервный режим монтирования через встроенную службу Windows WebClient.
   * **Переключатель в настройках**: Выбор движка доступен в окне «Настройки подключения».
2. **Полная независимость и универсальность**:
   * **Заменяет узкоспециализированные плагины** (включая плагин Total Commander): любая программа (Проводник, Total Commander, AIMP, VLC, утилиты бэкапов) работает с файлами в Telegram напрямую как с локальными или сетевыми файлами.
   * **Файловые операции**: Загрузка Drag&Drop, редактирование, создание папок, перемещение, переименование, удаление.
   * **Мгновенное серверное копирование (Zero-Traffic Copy & Forwarding)**: Копирование файлов и целых папок как в пределах одного канала, так и между разными каналами через `TL.Methods.Messages_ForwardMessages` с флагом `drop_author`. В WebDAV поддержан нативный метод `COPY` (RFC 4918), а в драйвере WinFsp входящая запись от Проводника Windows подтверждается мгновенно без повторного расхода интернет-трафика на заливку байтов в сеть (0 байт исходящего трафика).
   * **Мульти-канальное хранилище и динамическая привязка папок**: Возможность привязки любой папки диска (например, `Музыка`, `Фото`, `Рок`) к отдельному приватного каналу Telegram через контекстное меню Проводника («Привязать папку к отдельному каналу Telegram»). Автоматический форвардинг существующего содержимого, наследование каналов подпапками, авто-переименование и каскадная очистка неиспользуемых каналов.
   * **Музыкальная фонотека**: Плейлисты, обложки, извлечение ID3-тегов и моментальный Seek.
2. **Гибкие настройки конфигурации и изоляция данных хранилища**:
   * **Разделение Host vs Storage**:
     - Системные настройки хоста (`appsettings.json`): порт, буква диска, движок (WinFsp/WebDAV), параметры RAM кэша, воркеров и логирования. При случайном удалении JSON восстанавливается со встроенными дефолтами.
     - Данные авторизации и каналы Telegram (`base.db`): таблицы `telegram_accounts` и `telegram_channels`. Учетные данные и `StorageChannelId` с `access_hash` неразрывно привязаны к базе файлов `nodes` и защищены от потери.
   * **Переключатели режимов**: Независимые галочки `[x] Включить WebDAV сервер` и `[x] Монтировать как сетевой диск`.
   * **Авторизация в Telegram прямо из UI**: Встроенная форма авторизации (телефон, код SMS/Telegram, 2FA-пароль) без необходимости сторонних утилит.
   * **Снятие ограничений службы Windows WebClient и UAC (Патч реестра с авто-запросом UAC)**:
     - `BasicAuthLevel = 2`: разрешение монтирования WebDAV-диска по обычному HTTP без SSL-сертификатов.
     - `FileSizeLimitInBytes = 0xFFFFFFFF` (4 ГБ): снятие стандартного ограничения Windows в 50 МБ на размер передаваемого файла в Проводнике (ошибка `0x800700DF`). Позволяет без ошибок передавать и открывать большие FLAC-альбомы, образы и видео.
     - `EnableLinkedConnections = 1`: включение сквозного доступа к виртуальным дискам между сессиями администратора и обычного пользователя.
     - `ZoneMap`: добавление доверия в зону «Местная интрасеть» для подавления предупреждений безопасности Windows.
     - *Кнопка в UI сама запрашивает системное окно UAC Windows, избавляя от необходимости вручную запускать приложение от Администратора.*
     - *(Для сторонних плееров вроде AIMP и Total Commander твики не требуются, так как они работают напрямую по HTTP).*
   * **Настройка сетевого диска**: Выбор буквы (выбор любой свободной буквы или авто-выбор) и имени диска в системе.
   * **Управление емкостью и умное авто-расширение**: Выбор базового размера диска (от 10 ГБ до 1 ПБ, по умолчанию 1024 ГБ / 1 ТБ), подсчет реального занятого места из базы SQLite, авто-расширение емкости при заполнении > 70% (диск никогда не становится красным в Проводнике), опция учета корзины `.Trash` в занятом месте.
   * **Настройка портов и путей**: Выбор WebDAV-порта (по умолчанию `37000`), путей к базе `base.db`.
   * **Настройка корзины**: Параметры автоочистки и правил хранения версий.
3. **Полностью автономная работа "с нуля" (Zero Dependencies)**:
   * При первом запуске сервис **сам создает чистую базу данных SQLite** (`base.db`). Нет зависимости от старых плагинов Total Commander или сторонних баз.
   * Одно постоянное соединение Telegram (**`WTelegramClient`**).
   * Отсутствие конфликтов блокировок базы и сбросов сессий Telegram.
4. **Асинхронный неблокирующий логгер и вкладка «Логирование» в UI**:
   * Все системные события, ошибки WebDAV и статус подключения MTProto асинхронно записываются в текстовый лог `logs/app.log`.
   * **Управление уровнями логирования из UI**: Чекбоксы переключения детализации логов (`Debug`, `Info`, `Warn`, `Error`) с авто-сохранением в `appsettings.json`.
   * **Гибкая ротация файлов**: Настраиваемый в UI лимит размера одного файла лога (в МБ, по умолчанию 5 МБ) и количества хранимых архивов (по умолчанию 3 файла: `app.1.log`, `app.2.log` и т.д.).
   * **Живая статистика и быстрые действия в UI**:
     - Отображение текущего размера `app.log`, числа архивных файлов и суммарного объёма диска.
     - Кнопка **«📁 Папка с логами»** — быстрый переход к папке логов в Проводнике Windows.
     - Кнопка **«📄 Открыть app.log»** — моментальный просмотр действующего лог-файла в системном редакторе.
     - Кнопка **«🗑 Очистить логи»** — безопасная очистка логов прямо из программы.
   * Защита чувствительных данных (маскирование `api_hash` и ключей).
5. **Надежное резервное копирование базы данных SQLite в отдельный Telegram-канал**:
   * **Двухэтапный сброс WAL и монолитные снимки**: Нативный `PRAGMA wal_checkpoint(TRUNCATE);` сбрасывает все буферные транзакции в основной файл `base.db`, а `VACUUM INTO` создает изолированный чистый слепок без блокировки читателей и писателей.
   * **База данных как единый источник правды (Single Source of Truth)**: Реквизиты выделенного канала бэкапов (`channel_id`, `access_hash`) хранятся непосредственно в таблице `telegram_channels` базы `base.db` (`channel_type = 'backup'`). Запросы отправляются напрямую за 0 мс без перебора диалогов, а при переносе базы на новый компьютер связь с каналом сохраняется автоматически.
   * **Хронологическая история и авто-синхронизация названия**: База выгружается в приватный канал Telegram со сводной карточкой (имя ПК `Environment.MachineName`, дата, счетчик узлов/папок/файлов, размер и хэштег `#db_backup`). При изменении имени канала в настройках приложения новое название автоматически и безопасно обновляется в облаке Telegram без блокировки интерфейса.
   * **Автономное восстановление базы из Telegram**: Возможность в один клик восстановить базу данных на новом компьютере или после сбоя прямо из канала Telegram со сбросом пула соединений SQLite, созданием защитного локального снимка `base_pre_restore_*.db` и проверкой целостности.
   * **Тихая синхронизация между ПК (сценарий Дом/Работа)**: Моментальная проверка и применение свежей копии базы из Telegram при старте приложения строго ДО запуска WebDAV и монтирования диска WinFsp, а также по периодическому таймеру (по умолчанию 5 мин) и при выходе Windows из сна/гибернации (`PowerModes.Resume`, 5 сек). Сквозное логирование всех запросов в `logs/app.log`. Если свежая копия пришла с другого ПК и локально нет несохраненных изменений, база бесшовно накатывается с тихим уведомлением в системном трее.
   * **Блокировка выгрузки при конфликте версий (Root Cause Protection)**: Если облачная база не применилась из-за ошибки или на локальном ПК есть незалитые изменения при наличии свежей копии в Telegram, выгрузка базы в облако блокируется для защиты от перезаписи данных. Пользователю выводится предупреждение в трее, а в окне настроек доступно осознанное подтверждение принудительной выгрузки.
   * **Умные политики создания**: Авто-бэкап по Debounce-таймеру через 15 минут тишины после любых изменений диска, автоматическая отправка при выходе из программы и экстренная кнопка в системном трее Windows.
   * **Вкладка «Бэкап базы» в окне настроек**: Управление каналом, таймерами, ручной запуск, восстановление из Telegram и быстрый доступ к локальным архивам `backups/`.

### 🧩 4 ключевых компонента подсистемы чтения:

1. **`TelegramService.cs` (Главный диспетчер)**:
   * Принимает системные вызовы `Read` от WebDAV и WinFsp.
   * Ведет стейт-машину чтения `FileReadSequence` по каждому файлу (смещение, длительность, число последовательных блоков и накопленный объем).
   * **Двухуровневый адаптивный квант и схема первого мегабайта (256 КБ + 768 КБ)**:
     * **Режим зонда первой четверти (256 КБ)**: Скачивается ровно 256 КБ (`[Зонд 256 КБ - 1/4]`) для чтения ID3-тегов и заголовков обложек, экономя 75% сетевого трафика при просмотре папок и каталогизации.
     * **Монолитная докачка остатка (768 КБ)**: При чтении дальше первой четверти (признак копирования или воспроизведения) оставшиеся 768 КБ запрашиваются одним монолитным сетевым вызовом (`[Зонд 768 КБ - 2..4/4]`). Universal Interval Merger моментально сшивает обе части в готовый 1 МБ блок в ОЗУ, сокращая число запросов для старта копирования в 2 раза (с 4 до 2).
     * **Режим воспроизведения (1024 КБ)**: Со 2-го мегабайта все чанки качаются полноразмерными блоками по 1 МБ (`[Полный чанк]`) с параллельным префетчем воркеров.
     * **Хвостовые зонды**: Хвостовые атомы `moov`/`cues`/`zip` читаются квантами 256 КБ без паразитного префетча.
2. **`_chunkMemoryCache` (Кольцевой RAM-кэш, по умолчанию 128 МБ, настраивается в UI)**:
   * Обеспечивает мгновенный доступ без обращений к сети при повторных чтениях одних и тех же смещений операционной системой.
   * **Universal Interval Merger**: автоматически сшивает любые произвольные смежные и перекрывающиеся фрагменты в пределах 1 МБ слота в единый непрерывный буфер в памяти без повторных сетевых запросов.
   * Лимит емкости буфера и время жизни (TTL) гибко настраиваются пользователем в окне параметров («Буфер кэша в ОЗУ (МБ)» и «Время жизни кэша в ОЗУ (мин)»).
3. **`MtprotoDownloadWorkerPool.cs` (Единый постоянный пул воркеров — Singleton Worker Pool)**:
   * Реализует архитектуру долгоживущего сервиса воркеров MTProto (паттерн TDLib / Telegram Desktop). В приложении крутятся строго N настроенных воркеров (1–3).
   * Исключает создание временных конкурирующих пулов при многопоточном чтении плеера.
   * Атомарная дедупликация чанков в точке постановки в очередь: исключает дублирующие сетевые вызовы одних и тех же смещений.
   * Приоритетные очереди: синхронные запросы плеера (`isHighPriority`) обрабатываются в первую очередь, опережая фоновое упреждение.
   * Поддерживает горячее изменение числа воркеров и сквозную адаптацию задержки (пейсинг) без перезапуска сервиса.
4. **`NetworkTransferAudit` (Сетевой ревизор)**:
   * Ведет независимый учет всех байт, поступивших из сети Telegram MTProto и отданных клиентам из памяти ОЗУ.
   * В реальном времени рассчитывает процент завершенности и выводит финальную оценку сетевой эффективности (например, `1.00x — идеально, 0% дублирования`).

## ⚡ Функциональные модули и технические особенности

### 1. Чтение и Стриминг (GET, HEAD & Range Requests)
* **Адаптивные кванты MTProto (`Upload_GetFile`)**:
   - Полный отказ от фонового выкачивания файлов целиком при чтении диапазонов.
   - При чтении метаданных, тегов и генерации видео-эскизов Проводником Windows или плеером AIMP у Telegram запрашивается легковесный квант **256 КБ**, синхронизированный по выравниванию смещения.
   - Устранена первопричина паразитных зависаний и массового скачивания файлов при открытии папок с видеоклипами и сканировании фонотеки AIMP.
   - Мгновенный Seek (перемотка) в плеере: запрос произвольного смещения берет только необходимые байты прямо из облака.
   - Автоматическая маршрутизация к нужному дата-центру Telegram (`GetClientForDC` при `dc_id` документа или ошибке `FILE_MIGRATE_X`).
   - Мгновенное завершение: как только клиент закрывает соединение после чтения тегов или кадра, поток немедленно освобождается без лишних сетевых затрат.
* **Поддержка `HTTP 206 Partial Content` и `HTTP HEAD`**:
  - Отдача корректных заголовков `Content-Length`, `Content-Range: bytes X-Y/Total`, `Accept-Ranges: bytes` и `Last-Modified`.
  - Корректная обработка метода `HEAD` с проверкой по базе данных SQLite без передачи тела файла, обеспечивающая 100% совместимость с аудиоплеерами и Проводником Windows.
* **Стриминг "на лету" и защита от ложного скачивания**:
  - Файлы транслируются напрямую из Telegram без предварительного сохранения полного файла на жесткий диск.
  - **Универсальная защита метаданных (Format-Agnostic)**: чтение первого мегабайта (`#0`) и хвостовой зоны (последние 2 МБ, где располагаются MP4 `moov`, MKV cues, ZIP central directory, ID3v1) строго изолированы и никогда не приводят к выкачиванию файла.
  - **Умная докачка частичного чанка (Partial Chunk Tail Resumption)**: если в RAM уже находится частичный зонд метаданных (256 КБ), при последующем открытии полного файла или картинки воркеры MTProto докачивают строго недостающий остаток (768 КБ) со смещением 256 КБ, склеивая блоки в памяти без повторного скачивания первых 256 КБ и исключая артефакты и повреждения картинок.
  - **Направленный префетч**: при воспроизведении и стриминге упреждающая выкачка чанков ведется строго вперед от текущего положения ползунка (`startChunkOffset`), исключая скачивание пропущенных или ранее прочитанных фрагментов файла.

### 2. Запись, Редактирование и Версионирование (PUT & MKCOL)
* Все файлы загружаются в **отдельный приватный канал-хранилище Telegram** (по умолчанию `"Telegram WebDAV Drive"`, имя можно изменить в настройках). Это сохраняет личное «Избранное» (Saved Messages) чистым.
* Если канал ещё не создан, сервис автоматически создаёт приватный канал через MTProto API и сохраняет его ID в конфигурации.
* **Сквозной потоковый пайплайн (Zero-Temp Direct Streaming & TCP Flow Control)**:
  - Исключена промежуточная запись файлов на локальный диск при штатной загрузке (`StreamingUploadStream` в WebDAV и `StreamingPipeStream` в WinFsp).
  - Входящий поток от Проводника передается напрямую в MTProto-клиент порциями по 512 КБ (`Upload_SaveBigFilePart`) с обратным давлением (Backpressure).
  - **Smart Source Detection (хэндлы ядра Windows explorer.exe и буфер обмена CF_HDROP)**: при перетаскивании мышкой из Проводника или вставке файлов и каталогов (`Ctrl+C` / `Ctrl+V`) видео-превью, фото-галереи, стоп-кадры, габариты и длительность считываются декодерами Windows напрямую из исходных файлов (включая вложенные файлы внутри скопированных папок на диске `D:` или Рабочем столе), полностью сохраняя превью и метаданные без промежуточного копирования гигабайт на системный диск `C:`. Детерминированная модель сессии (`CopySession`, Zero Timers) отслеживает точный состав пачки (`PendingFiles`) и каталоги источников (`SourceRoots`), поштучно вычеркивает обработанные файлы и автоматически завершает сессию при исчерпании списка без единого таймера. Внедрена защита от дедлоков при опросе дескрипторов (фильтрация ядерных путей WinFsp `\DEVICE\WINFSP` и жесткий лимит времени сканирования 100 мс).
  - Для аудиофайлов парсер `AudioMetadataExtractor` считывает первые 256 КБ тегов прямо в ОЗУ (или из оригинала) и продолжает сквозной стриминг без сохранения гигабайтных файлов на диск `C:`.
* **Нативная отправка аудио-треков и онлайн-стриминг в Telegram (Audio Streaming > 10 МБ)**:
  - Все аудиофайлы (`.mp3`, `.flac`, `.m4a`, `.ogg`, `.wav`, `.aac`, `.opus`, `.wma`) отправляются в канал Telegram с атрибутом `DocumentAttributeAudio` (название, исполнитель, длительность) и правильным MIME-типом (`audio/mpeg`, `audio/flac` и т.д.).
  - Полностью устранено ограничение Telegram-клиентов на 10 МБ: аудиофайлы любого размера (15 МБ, 50 МБ, 100 МБ FLAC и т.д.) распознаются клиентами Telegram как полноценные музыкальные треки, попадают во встроенный плеер и стримятся мгновенно с первой секунды без ручного скачивания на диск.
  - Автоматическая передача вшитых обложек альбомов (`thumb`): обложка трека (APIC / ID3v2 / FLAC) загружается и прикрепляется к сообщению в Telegram как официальная обложка альбома.
  - Чистые имена: если мета-теги внутри файла отсутствуют, в названии трека сохраняется оригинальное имя файла без расширения (без принудительного разделения по дефису).
* **Полноценная поддержка видео со стримингом и обложками (Video Streaming & Fast Playback)**:
  - Видеофайлы (`.mp4`, `.mkv`, `.avi`, `.mov`, `.webm`, `.wmv`, `.flv`, `.m4v`, `.ts`, `.3gp`) отправляются в Telegram как полноценные видеозаписи с атрибутом `DocumentAttributeVideo` и флагом `supports_streaming`.
  - Моментальное воспроизведение в плеере Telegram на ПК и смартфонах без предварительного скачивания всего файла на диск.
  - **Двухуровневый каскад генерации стоп-кадров (thumbnails)**:
    1. **Аппаратный Media Foundation (GPU / NV12)**: Прямое аппаратное декодирование видеокадров без сторонних утилит и процессов.
    2. **Интеграция с K-Lite Codec Pack / Icaros / Windows Shell (`IShellItemImageFactory`)**: Для форматов без встроенного системного декодера Windows (AV1, MKV, VP9, WebM, FLV) сервис автоматически запрашивает стоп-кадр у движка K-Lite / Shell Thumbnail Provider.
  - **Рекомендация по кодекам**: Для гарантированного отображения эскизов видео абсолютно всех форматов (включая AV1 и MKV) в Проводнике Windows и Telegram рекомендуется установить бесплатный пакет **K-Lite Codec Pack (Standard)** или системный компонент **«Расширение для видео AV1»** от Microsoft.
  - Автоматическое масштабирование и сжатие обложки под стандарты Telegram (до 320x320 JPEG, качество 85).
  - Точное определение разрешения (Width, Height) и длительности (Duration) с поддержкой парсинга MP4-атомов (`tkhd`, `mvhd`).
  - Чистая база данных SQLite: видеофайл хранится как обычный файловый узел без тяжелых бинарных BLOB-полей и избыточных тегов.
* **Живой HUD-виджет прогресса в системном трее (`TrayProgressOverlay`)**:
  - Всплывающее без перехвата фокуса (`WS_EX_NOACTIVATE`) окно карточки в правом нижнем углу над панелью задач.
  - Автоматическое появление при старте отправки любого файла, либо показ при наведении курсора на иконку в трее (настраивается в параметрах).
  - Динамическое обновление каждые 200–250 мс в реальном времени: имя файла, градиентный прогресс-бар, процент, переданный объем (`X из Y МБ`) и скорость отдачи в интернет (`МБ/с`).
  - Плавное закрытие через 1.5 секунды после успешного завершения передачи.
* **Сохранение оригинальных временных меток (Timestamps Persistence)**:
  - Сервер полноценно обрабатывает метод `PROPPATCH` (`Win32LastModifiedTime`, `Win32CreationTime`, `getlastmodified`, `creationdate`) и заголовки `Last-Modified` / `X-OC-MTime` при `PUT`.
  - Оригинальные даты создания и изменения файлов из исходных папок сохраняются в SQLite базе данных `base.db` и отдаются клиентам с поддержкой пространства имен `urn:schemas-microsoft-com:`.
  - Обеспечивает 100% совместимость с программами резервного копирования и синхронизации (Allway Sync, FreeFileSync, GoodSync) и сохраняет оригинальные исторические даты изменения при обычном копировании через Проводник Windows и Total Commander.
* **Автоматическое создание структуры родительских каталогов (On-Demand Parent Path Creation)**:
  - При синхронизации каталогов через Total Commander, rclone или утилиты автоматического бэкапа клиенты могут сразу отправлять запрос `PUT` на вложенный путь файла (например, `/hhh/big/track.mp3`) без предварительного вызова `MKCOL` для каждого промежуточного каталога.
  - Метод `EnsureDirectoryPathExists` автоматически и атомарно создает всю цепочку недостающих промежуточных папок в SQLite на лету перед сохранением файла, устраняя ошибку `409 Conflict` и прерывание закачки в Total Commander.
* **Умная система подписей в Telegram и мгновенный поиск (#latest / #trash)**:
  - **Актуальный файл на диске**:
    ```text
    🟢 /Документы/Отчет_v3.docx
    ID: 1487
    #latest
    ```
  - **Архивная ревизия или файл в Корзине**:
    ```text
    🗑️ /Документы/Отчет_v3.docx
    ID: 1487
    #trash
    ```
  - **Автоматическая ротация версий**: При появлении версии `v4` сервис отправляет новый файл с маркером `🟢 #latest` и точным `ID`, а предыдущее сообщение `v3` через персистентную очередь `pending_caption_updates` автоматически редактируется на `🗑️ #trash`.
  - **Мгновенный поиск**: В клиенте Telegram достаточно ввести `#latest Название` или кликнуть по хэштегу `#latest`, чтобы видеть исключительно актуальные рабочие файлы без промежуточных ревизий и мусора.
* **Интеграция «Открыть в Telegram» в контекстное меню Проводника Windows**:
  - В контекстное меню файлов на виртуальном диске добавляется пункт **«Открыть в Telegram»** (с фильтром `AppliesTo`, только для файлов виртуального диска).
  - По клику приложение мгновенно открывает Telegram Desktop (или браузер) напрямую на сообщении канала с этим файлом (`https://t.me/c/.../<message_id>`).
* При редактировании или пересохранении файла на сетевом диске:
  1. Сервис загружает обновленный файл в приватный канал Telegram через `WTelegramClient`.
  2. В базе `base.db` создает новую версию файла с префиксом/версией `v2`.
  3. Старая версия `v1` мягко переносится в виртуальную корзину (`.Trash` / `Корзина`), а её подпись в Telegram переводится в статус `🗑️ #trash`.

### 3. Настраиваемая Виртуальная Корзина (Soft Delete & Restore)
* **Безопасное удаление**: При нажатии «Удалить» в любой программе файл не удаляется из Telegram сразу, а перемещается в виртуальную корзину (`.Trash`) с сохранением структуры каталогов.
* **Защита от случайного уничтожения**: Сама папка `.Trash` защищена от удаления и переименования снаружи (как в WebDAV, так и в WinFsp через возврат `NT_STATUS_CANNOT_DELETE`).
* **Чистый корень диска (`HideTrashFromRoot`)**: Папка `.Trash` автоматически скрывается из листинга корня диска, оставляя рабочую область диска эстетичной и защищая от случайных действий.
* **Нативная интеграция в контекстное меню Windows**: В реестр пользователя (HKCU) добавляется пункт «Открыть корзину WebDAV» с системной иконкой корзины при клике правой кнопкой мыши по диску или по пустому месту в Проводнике, а также пункт быстрого перехода в меню системного трея.
* **Гарантированное перманентное удаление (Transactional Deletion Queue / Outbox Pattern)**:
  - При удалении файлов или папок из корзины строки атомарно удаляются из файловой структуры SQLite за 1 мс, обеспечивая мгновенный отклик Проводника Windows без зависаний интерфейса.
  - Все ID сообщений Telegram (включая сообщения-превью галереи) сохраняются в персистентную таблицу `pending_deletions (id, tg_message_id, created_at)`.
  - **Чисто событийная обработка (Event-Driven)**: при пустой очереди фоновый воркер находится в глубоком сне и не производит холостых запросов к базе (0% CPU и дисковой нагрузки). Воркер пробуждается мгновенно (0 мс) при поступлении нового удаления, а также разово при запуске приложения / входе в Telegram.
  - **Надежность при сбоях и гибернации**: если во время удаления пропал интернет или возник `FLOOD_WAIT`, воркер повторяет попытки пакетами (до 100 сообщений с алгоритмом биссекции) исключительно до тех пор, пока таблица `pending_deletions` не станет пустой, после чего сразу засыпает. По завершении очистки через 3 секунды тишины автоматически запускается VACUUM базы данных.
* **Версионный архив**: Предыдущие версии отредактированных файлов (`_v1`, `_v2`) также доступны в корзине для легкого восстановления.
* **Автоочистка**: В настройках сервиса можно задать срок хранения файлов в корзине (например, 30 дней, либо отключить автоочистку).

### 4. Оптимизация фонотеки и защита от BAN / FloodWait
* **Сверхлегкая база данных SQLite (`base.db`)**: База данных отвечает исключительно за структуру виртуальной файловой системы (пути, папки, даты, размеры, Telegram Message ID и `inline_data` для микрофайлов `<= 1` байта). Рудиментарные колонки тегов удалены, благодаря чему база на десятки тысяч треков весит считанные мегабайты и работает молниеносно. Системные папки `Root` (ID = 1) и `.Trash` (ID = 2) создаются атомарно при инициализации схемы базы.
* **Интеллектуальная оптимизация базы (Auto-VACUUM с дебаунсом и ручное сжатие в UI)**:
  - При очистке файлов из корзины `.Trash` сервис автоматически инициирует фоновое сжатие освободившихся страниц базы через 3 секунды затишья, предотвращая блокировки при массовом удалении.
  - В окне «Настройки» на вкладке «База» доступен блок «База данных SQLite» с живым размером файла на диске, кнопкой оптимизации в один клик «🗜 Сжать базу (VACUUM)» и кнопкой быстрого перехода в папку с файлом базы.
* **Автоматическое резервное копирование и восстановление из Telegram (Cloud Backup & Restore)**:
  - **Консистентные снимки (VACUUM INTO)**: создание монолитных копий базы в фоновом режиме без блокировки доступа к диску.
  - **Автобэкап по таймеру и при выходе**: выгрузка в приватный канал Telegram (`channel_type = 'backup'`) после 15 минут тишины при изменениях и перед закрытием программы.
  - **Восстановление в 1 клик**: в окне настроек доступна кнопка «📥 Восстановить базу из Telegram», которая находит последнюю версию базы в облаке, создает локальный защитный снимок текущего состояния и безопасно накатывает базу без потери данных.
  - **Тихая синхронизация между ПК (сценарий Дом/Работа)**: немедленная проверка ДО монтирования диска при старте, фоновый таймер проверки (по умолчанию 5 мин), мгновенный триггер при восстановлении связи с Telegram (`Connected to DC`) и аппаратный сторож сна (Time-Leap Watcher). Если свежий бэкап пришел с другого ПК и локально нет несохраненных правок, база обновляется автоматически без модальных окон, выводя тихое уведомление в трее.
* **Потоковый On-Demand стриминг и защита от паразитного трафика при наведении курсора / сканировании тегов**:
  - При наведении курсора мыши в Проводнике или сканировании тегов плеером AIMP / foobar2000, система запрашивает только первые 128–256 КБ заголовка файла.
  - Первый же принятый блок байт мгновенно транслируется клиенту из ОЗУ без выкачивания всего файла целиком.
  - Интеллектуальный пул воркеров (`MtprotoDownloadWorkerPool`) с кэшированием в оперативной памяти гарантирует отсутствие повторных запросов в Telegram и защищает от `FLOOD_WAIT`.
  - Никаких фиктивных `desktop.ini`: пользователь сохраняет полный контроль над видом папок в Windows (включая вид «Музыка»).

### 5. Потоковая передача и докачка (Streaming & Range Support)
* **Потоковая прямая загрузка в Telegram (Zero-Temp Streaming)**:
  - При отправке файла с ПК в Telegram передача осуществляется на лету без промежуточной буферизации на локальный диск (`Zero-Temp`) и без создания временных файлов `.part`.
  - Встроенный механизм TCP Flow Control синхронизирует скорость чтения клиента с пропускной способностью Telegram API, обеспечивая реальный прогресс-бар в Проводнике Windows.
* **Докачка при скачивании из Telegram на ПК (Download Resume)**:
  - WebDAV-сервер отдает заголовки `Accept-Ranges: bytes` и статус ответа `206 Partial Content`.
  - Любой клиент с поддержкой HTTP Range (браузер, менеджер загрузок, curl) может запросить произвольный диапазон байт и возобновить прерванную загрузку без повторного скачивания всего файла с нуля.

### 6. Память и Производительность
* Буферизация через `ArrayPool<byte>.Shared` (Zero-allocation streaming).
* Среднее потребление RAM сервисом: **~20–35 МБ**.
* Встроенные нативные биндинги WinFsp на C# без внешних устаревших зависимостей (`winfsp.net`), с поддержкой прямого запуска из Self-Contained Single-File сборки без дисковых костылей.

### 7. Архитектура MTProto скачивания и стриминга (Скачивание и Prefetch)

#### Как было (проблема коллизий и дублирования):
* В методе `DownloadFileAsync` одновременно сосуществовали конкурирующие механизмы выкачки:
  1. Фоновый предзагрузчик `TriggerContinuousPrefetch`, запускавший отдельный пул из 3 воркеров на файл.
  2. Прямой `DownloadToStreamAsync`, также создававший собственный независимый пул из 3 воркеров.
  3. Точечные прямые RPC-запросы `Upload_GetFile` для зондирования метаданных и мелких фрагментов.
* **Следствие:** При чтении файла запускались одновременно два пула (до 6 воркеров суммарно), которые не знали о сетевых запросах друг друга. В результате одинаковые чанки (например, #1, #2) запрашивались из Telegram дважды параллельно, порождая избыточный трафик (эффективность 1.25x вместо 1.00x) и гонки за порядок получения данных.

#### Как будет (поэтапная эволюция к эталонной архитектуре):
* **Этап 1 (Устранение дублирования и коллизий пулов):**
  - Исключение создания второго пула `workerPool` в теле `DownloadFileAsync`: фоновый конвейер `ContinuousPrefetch` становится единственным поставщиком чанков для файла.
  - Потоковое чтение WebDAV выступает чистым потребителем (Consumer): читает готовые данные из RAM-кэша или ожидает завершения текущего чанка через `_inFlightChunkWaiters`.
  - Воркеры пула при обнаружении чанка в RAM или в активной закачке другим воркером **не дублируют запрос в сеть**, а переходят к следующему свободному чанку из очереди (полная утилизация воркеров без простоя).
  - Результат: строгая утилизация 3 воркеров, последовательность чтения #1, #2, #3... и строго 1.00x сетевая эффективность (0% потерь).
* **Этап 2 (Глобальный приоритетный диспетчер Global Chunk Scheduler):**
  - Вынос единого пула из 3–4 воркеров на общесистемный уровень (`TelegramService`) для всех одновременно открытых файлов.
  - Единая очередь с приоритетами:
    - *Приоритет 1 (Критический):* Чанк, необходимый прямо сейчас для сокета WebDAV (воспроизведение/копирование).
    - *Приоритет 2 (Высокий):* Зонды метаданных и эскизов.
    - *Приоритет 3 (Фоновый):* Упреждающее скользящее окно предзагрузки.
  - Надежная защита от FLOOD_WAIT при параллельном открытии десятков файлов в проводнике или плеере.

### 8. Непрерывная интеграция и релизы (GitHub Actions)
* Конфигурация в файле `.github/workflows/release.yml`.
* Автоматическая сборка под **Windows x64** на раннере `windows-latest` при каждом пуше в ветки `main` / `master`.
* Автоматический инкремент версии на каждый пуш: `1.0.${{ github.run_number }}` (1.0.1, 1.0.2...).

* Автоматическая публикация в **GitHub Releases** с тегом `v1.0.${{ github.run_number }}` (архив `.zip` и прямой `.exe`).

### 9. Единая система дизайна интерфейса (UI Design System: `UITheme` & `UIFactory`)
* **Архитектурная защита от багов WinForms**:
  - Все рамки `GroupBox` создаются через `UIFactory.CreateGroupBox(...)` со строгой гарантией `MinimumSize` и ширины `510 px`, что полностью исключает баг вертикального схлопывания текста при `FlowDirection.TopDown`.
  - Строки параметров собираются через `UIFactory.CreateSettingRow(...)` с компактной 2-колоночной сеткой (`TableLayoutPanel`): подпись слева + поле ввода сразу справа на одной вертикальной оси (без разрывов через всё окно).
  - Нижняя фиксированная панель действий формы (`UIFactory.CreateBottomBar`): кнопки «Сохранить» и «Закрыть» всегда на виду внизу окна и не уезжают под скроллбар.
* **Стандарты типографики и стилей (`UITheme`)**:
  - Базовый шрифт: `Segoe UI, 9pt, Regular` (системный стандарт Windows).
  - Заголовки: `Segoe UI, 9pt, Bold` / `9.5pt, Bold`.
  - Подсказки: `Segoe UI, 8.5pt, Regular` (приглушенный цвет `#6E6E6E`).
  - Стандартная высота кнопок: `30 px` (обычные), `34 px` (акцентные).

### 10. Поддержка файлов произвольного размера свыше 2 ГБ / 4 ГБ (Raw Binary Chunking & node_parts)
* **Преодоление лимитов протокола MTProto**:
  - Серверы Telegram MTProto отклоняют документы размером свыше 2 000 МБ (~1.95 ГБ) для обычных пользователей и свыше 4 000 МБ (~3.90 ГБ) для пользователей с подпиской Telegram Premium.
  - Сервис автоматически определяет премиум-статус текущего аккаунта (`CurrentUser.IsPremium`) и выставляет фиксированный размер части с кратностью MTProto-блоку (1 048 576 байт): `2 097 152 000` байт (~1.95 ГБ) либо `4 194 304 000` байт (~3.90 ГБ).
* **Изолированная таблица сегментов `node_parts` (Архитектурная чистота VFS)**:
  - Основная таблица файлов `nodes` содержит ровно одну запись на файл с его реальным общим размером (например, 25 ГБ) и ID заглавного сообщения.
  - Проводник Windows, файловый менеджер и все существующие методы выборки каталогов (`GetChildNodes`, `GetNodeByPath`, `SearchNodes`, подсчет размера папок) работают без изменений и гарантированно не видят дубликатов.
  - Сегменты хранятся в выделенной таблице:
    ```sql
    CREATE TABLE IF NOT EXISTS node_parts (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        node_id INTEGER NOT NULL,
        part_index INTEGER NOT NULL,
        part_size INTEGER NOT NULL,
        tg_message_id INTEGER NOT NULL,
        tg_channel_id INTEGER NOT NULL,
        created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
        FOREIGN KEY (node_id) REFERENCES nodes(id) ON DELETE CASCADE,
        UNIQUE(node_id, part_index)
    );
    CREATE INDEX IF NOT EXISTS idx_node_parts_node ON node_parts(node_id);
    ```
* **Потоковый адаптер `BoundedStream` (Zero-Temp Upload)**:
  - Реализован потоковый ограничитель, который последовательно отрезает от входящего сокета WebDAV или пайпа WinFsp ровно заданный квант части и возвращает EOF для `WTelegramClient` без закрытия базового соединения.
  - Позволяет выгружать файлы любого размера (4K видео 20–50 ГБ, ISO-образы, базы данных) напрямую из сетевого потока без создания временных файлов на диске C:.
* **Связка сообщений в Telegram и разметка треда**:
  - Часть 0 загружается как основное сообщение в канале с обложкой/видео-превью и маркером `[Часть 1 из N, total=...Bytes] #latest`.
  - Части `1..N` загружаются как прямые ответы (`reply_to_msg_id = masterMessageId`), собираясь в аккуратный изолированный тред внутри канала, с именованием томов `${fileName}.002`, `${fileName}.003` и т.д.
* **Прозрачный стриминг и мгновенный Seek (`DownloadMultiPartFileAsync`)**:
  - При запросе диапазона байтов сервер вычисляет, в какую часть попадает глобальное смещение.
  - Произвольная перемотка (например, прыжок на 15-й ГБ) адресует сразу нужную часть без трогания предшествующих.
  - Если запрашиваемый диапазон пересекает стык частей, запрос прозрачно разбивается на два подзапроса и склеивается в непрерывный поток данных для плеера.
* **Транзакционная очистка сообщений (`EnqueuePermanentDeletion`)**:
  - При удалении составного файла `NodeRepository` автоматически подтягивает `tg_message_id` всех связанных частей из `node_parts` и помещает их в очередь гарантированного удаления `pending_deletions`, исключая потерю сообщений в Telegram.
