# ROADMAP & Progress Tracker (Universal WebDAV & Network Drive Service)

Документ отслеживания этапов разработки универсального C# WebDAV-сервиса и сетевого диска Telegram.

* Реестр принятых технических решений, исследованных гипотез и первопричин (Root Causes): [`DECISIONS_LOG.md`](./DECISIONS_LOG.md).
* Архивная дорожная карта версии V1 (AIMP Plugin) сохранена в файле: [`ROADMAP_V1_AIMP_PLUGIN.md`](./ROADMAP_V1_AIMP_PLUGIN.md).

---

## 📌 Текущий статус проекта
- **Фаза**: Реализованы все модули C# сервиса: база данных SQLite WAL, WebDAV сервер, WTelegramClient с защитой FLOOD_WAIT, парсер тегов ATL.NET, TrayContext и форма настроек WinForms.
- **Целевая платформа**: Windows Desktop / C# (.NET 8.0/9.0) Tray App & Background Service.
- **Протокол**: WebDAV (`http://localhost:{port}/`, настраиваемый порт) + Автомонтирование сетевого диска (`Z:`, `T:`, `Y:`, `W:` или авто-выбор).

### [x] Этап 2: Универсальный C# WebDAV Сервер

- [x] Логика обработки перезаписи файлов: сохранение прежней версии как `v1` в корзину и присвоение текущему файлу версии `v2`.
- [x] Виртуальное отображение папки корзины (`Z:\.Trash` / `Z:\Корзина`) и механизм восстановления предыдущих версий. Исправлен баг отображения файлов в `.Trash` (добавлена умная выборка `is_deleted = 1` при чтении корзины).
- [x] Зеркалирование структуры каталогов в корзине: при удалении файлов или вложенных папок сохраняется их точный исходный путь внутри `.Trash` (например, `Z:\.Trash\Album\CD1\track.mp3`), предотвращая свалку файлов в корне корзины и потерю структуры папок при удалении через Проводник Windows.
- [x] Реализация полноценного перманентного удаления (Transactional Deletion Queue / Outbox Pattern):
  - При очистке корзины `.Trash` или удалении файлов из нее записи атомарно удаляются из файловой структуры SQLite за 1 мс, исключая зависания Проводника Windows.
  - Все ID сообщений Telegram (включая сообщения-превью) переносятся в персистентную очередь `pending_deletions`.
  - Фоновый воркер `ProcessDeletionQueueAsync` в `TelegramService` работает по чисто событийной модели (Event-Driven): при пустой очереди находится в глубоком сне (0% холостой нагрузки на CPU и SQLite), а при удалении мгновенно вычищает файлы из канала Telegram пачками до 100 сообщений с алгоритмом биссекции и учетом `FLOOD_WAIT`. Защищен от обрывов сети, режима сна и гибернации (повторяет попытки только при наличии записей и подхватывает очередь при старте/реконнекте).
  - Рекурсивный обход поддерева `GetSubtreeNodes` исключает появление потерянных файлов-сирот при удалении папок.
  - Драйвер WinFsp защищает системную папку `.Trash` от удаления (`NT_STATUS_CANNOT_DELETE`).
- [x] Отказоустойчивое пакетное удаление из Telegram с бинарным делением (Биссекция): при возникновении ошибок типа `MESSAGE_ID_INVALID` (например, для файлов, удаленных ранее вручную в клиенте Telegram) пакет делится пополам, позволяя успешно и быстро удалить все валидные сообщения за минимальное число обращений к API.
- [x] Исправление первопричины появления дубликатов в корзине: универсальная обработка двухэтапного создания файлов Проводником Windows (0-байтовый плейсхолдер) и плагином WebDAV Total Commander (1-байтовый pre-flight probe). Файлы $\le 1$ байта больше не отправляются в Telegram впустую и не улетают в корзину при наполнении реальным содержимым, а обновляются на месте с версией 1. При необходимости 1 байт сохраняется локально в SQLite и отдается клиентам без обращения к Telegram.
- [x] Исправление бага восстановления/перемещения (`MoveNode`): корректный сброс флага `is_deleted = 0` при переносе из корзины и установка `is_deleted = 1` при переносе в корзину с рекурсивным обновлением вложенных элементов папок.
- [x] Реализация заголовков `Accept-Ranges: bytes` и статуса `206 Partial Content` для быстрой перемотки и докачки файлов на ПК.
- [x] Полноценная поддержка сохранения оригинальных временных меток файлов (Timestamps / LastModified / CreationDate):
  - Полноценная обработка метода `PROPPATCH`: извлечение свойств `<Win32LastModifiedTime>`, `<Win32CreationTime>`, `<getlastmodified>`, `<creationdate>` и сохранение реальных дат в базе SQLite (`updated_at`, `created_at`).
  - Поддержка заголовков `Last-Modified` и `X-OC-MTime` непосредственно в запросах `PUT` для установки точного времени файла с момента создания.
  - Добавление пространства имен `xmlns:Z="urn:schemas-microsoft-com:"` и тегов `<Z:Win32CreationTime>`, `<Z:Win32LastModifiedTime>` в ответы `PROPFIND`.
  - Устранение двойного сдвига часовых поясов (разницы в 3 часа): явная фиксация `DateTimeKind.Utc` при чтении из базы данных SQLite, исключающая повторную конвертацию локального времени при отдаче HTTP-заголовков.
  - Устранение ложных срабатываний и предупреждений «Папка назначения содержит более новые данные» в утилитах синхронизации (Allway Sync, FreeFileSync, GoodSync) и сохранение исторической даты изменения файлов при копировании через Проводник Windows и Total Commander секунда в секунду.

  - Единая строгая подпись (Caption) для всех файлов: формат `/Полный/Путь/Имя_vN.ext` (начиная с `_v1.ext` при создании и `_v2.ext` при перезаписи) для Проводника, Total Commander и Allway Sync.

При массовом удалении файлов в корне (Ctrl+A -> Delete) запрос на удаление самой корзины завершается статусом `204 NoContent` без уничтожения данных, позволяя клиентам (Проводник, Total Commander) безопасно переместить все пользовательские файлы в `.Trash`, сохранив их структуру и защитив от безвозвратного стирания в Telegram. Перманентное удаление файлов внутри корзины (`DELETE /.Trash/*`) сохраняет свою работоспособность.

  - Автоматическая ротация: при загрузке версии `v(N+1)` предыдущее сообщение `vN` через персистентную очередь `pending_caption_updates` SQLite безопасно редактируется в Telegram со сменой статуса на `#trash`.
  - Мгновенная фильтрация по клику на хэштег `#latest` в клиенте Telegram без отображения устаревших версий.

  - Регистрация пункта в HKCU через `ShellContextMenuHelper` для файлов сетевого диска с фильтрацией `AppliesTo`.
  - Обработка ключа `--open-in-tg` в `Program.cs` с мгновенным переходом к сообщению в Telegram Desktop (`https://t.me/c/...`).
- [x] Оптимизация потокового чтения и защита от скачивания при наведении курсора (InfoTip & Property Handlers):
  - Потоковый On-Demand стриминг из Telegram через `TeeStream`: одновременная отдача байт клиенту и сохранение в локальный дисковый кэш.
  - Адаптивный пейсинг первого блока (Initial Chunk Pacing): сервер мгновенно (за 0 мс) отдает первые 128 КБ заголовка клиенту, а затем делает короткую паузу (250 мс) для проверки активности сокета.
  - Мгновенное прерывание передачи: как только Проводник Windows считывает ID3-теги из первых 128 КБ для всплывающей подсказки (InfoTip) и закрывает дескриптор файла, сессия скачивания из Telegram немедленно прерывается. Файлы целиком (10–50 МБ) при наведении курсора не выкачиваются.
  - Бесшовное воспроизведение: при непрерывном воспроизведении в плеере (AIMP) или копировании первые 128 КБ дают более 3 секунд буфера звука, после чего трек продолжает скачиваться и кэшироваться на полной скорости без задержек.
  - Компактная архитектура SQLite: в базе данных хранятся только числовые и текстовые метаданные (название, артист, длительность и т.д.) без тяжелых бинарных BLOB-блоков, что сохраняет размер базы на уровне ~20 МБ даже для 60 000 треков.
  - Чистая файловая система: отсутствие искусственных файлов (`desktop.ini`), что сохраняет нативную поддержку любых режимов отображения папок Windows (включая вид «Музыка»).
