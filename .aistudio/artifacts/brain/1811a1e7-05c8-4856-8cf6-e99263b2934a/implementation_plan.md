# Восстановление базы данных base.db из Telegram

Автоматическое обнаружение, скачивание и безопасное накатывание последней актуальной резервной копии базы данных SQLite из закрытого канала бэкапов Telegram с защитой текущего состояния и нулевым риском потери данных.

### User Review & Critical Decisions

> [!IMPORTANT]
> При восстановлении базы данных из Telegram текущая локальная база будет замещена версией из облака. Для 100% гарантии сохранности данных перед заменой приложение автоматически создаст аварийный локальный снимок `base_pre_restore_backup.db`.

- **Подтвержденный выбор (Фаза 1)**: Приоритетный сценарий — восстановление базы данных из резервной копии.
- **Подтвержденный источник (Фаза 1)**: Автоматическая загрузка свежей копии напрямую из Telegram-канала бэкапов.
- **Стратегия безопасности**: Создание аварийного локального бэкапа перед заменой + онлайн-восстановление или безопасная ротация файлов без блокировок процесса (`WAL mode`).

---

### 1. Overview & Core Concept

- **Что делает функция**: Добавляет возможность в один клик восстановить структуру виртуального диска и файлов Telegram на новом ПК или при повреждении локальной базы, скачав актуальный снимок `base.db` из канала резервных копий Telegram.
- **Целевая аудитория**: Пользователь приложения, перенесший программу на новый компьютер, либо желающий откатить структуру каталогов к последней сохраненной копии.
- **Ключевая ценность**: Полная автономность и независимость от ручного копирования файлов базы между компьютерами — достаточно войти в свой Telegram-аккаунт и нажать кнопку восстановления.

---

### 2. User Experience & Visual Design

#### Основной сценарий использования (User Flow)
1. Пользователь открывает окно настроек на вкладке «Бэкап базы».
2. В блоке управления бэкапами видит новую акцентную кнопку «Восстановить базу из Telegram».
3. При нажатии на кнопку:
   - Приложение проверяет авторизацию Telegram.
   - Выполняет быстрый опрос канала резервных копий (`Messages_GetHistory`) и находит последний документ с хэштегом `#db_backup`.
   - Отображает диалоговое окно подтверждения с деталями найденной копии:
     * Дата и время создания;
     * Устройство-источник (компьютер);
     * Размер базы данных и количество узлов.
4. После подтверждения пользователем:
   - Скачивает документ во временный файл `backups/restore_incoming.db`.
   - Создает аварийную копию текущей базы `backups/base_pre_restore_TIMESTAMP.db`.
   - Безопасно накатывает базу через SQLite Online Backup API или безопасную перезагрузку соединений.
   - Оповещает пользователя об успешном завершении и обновляет структуру дерева в памяти.

### 3. Key Product Decisions & Trade-Offs

- **Решение 1: Механизм применения снимка базы данных**
  - *Выбранный подход*: Использование SQLite Online Backup API (`SqliteConnection.BackupDatabase`) либо контролируемый сброс пула соединений с заменой файла на диске.
  - *Почему*: В SQLite в режиме WAL (`Write-Ahead Logging`) открытые дескрипторы соединений вызывают ошибку доступа Windows (`IOException`), если попытаться напрямую перезаписать файл `base.db`. Использование штатного API резервного копирования или явный `SqliteConnection.ClearAllPools()` исключает сбои доступа.
  - *Альтернативы*: Принудительный перезапуск всего приложения через `Process.Start` — рабочий, но менее комфортный для пользователя вариант.

- **Решение 2: Защитный снимок перед накатыванием (Safety Snapshot)**
  - *Выбранный подход*: Обязательное создание резервной копии текущей локальной базы перед заменой.
  - *Почему*: Защита от случайного нажатия или ситуации, когда в облаке лежит более старая база, чем на текущем устройстве.

### 4. Technical Architecture & Data Strategy

```
┌─────────────────────────────────────────────────────────┐
│              WinForms UI (AuthSettingsForm)             │
│        Кнопка: «Восстановить базу из Telegram»          │
└────────────────────────────┬────────────────────────────┘
                             │ Запрос восстановления
                             ▼
┌─────────────────────────────────────────────────────────┐
│               DatabaseBackupService                     │
│  - GetLatestTelegramBackupInfoAsync()                   │
│  - RestoreDatabaseFromTelegramAsync()                   │
└──────────────┬───────────────────────────┬──────────────┘
               │                           │
  1. Скачивание файла                      │ 2. Безопасная накатка
               ▼                           ▼
┌───────────────────────────┐ ┌───────────────────────────┐
│      TelegramService      │ │      DatabaseManager      │
│ - Messages_GetHistory     │ │ - Safety snapshot         │
│ - DownloadBackupDocument  │ │ - ClearAllPools / Restore │
└───────────────────────────┘ └───────────────────────────┘
```

#### Компоненты и методы:
1. **`TelegramService.cs`**:
   - `GetLatestBackupMessageAsync()`: поиск последнего сообщения в бэкап-канале с медиа-документом базы данных.
   - `DownloadBackupDocumentAsync(document, targetStream)`: потоковая загрузка файла из Telegram без избыточного использования памяти.
2. **`DatabaseBackupService.cs`**:
   - `RestoreFromLatestTelegramBackupAsync(IProgress<int> progress)`: оркестрация процесса (проверка, скачивание, защитный снимок, накат).
3. **`DatabaseManager.cs`**:
   - `RestoreFromSnapshot(string snapshotFilePath)`: атомарная замена `base.db` со сбросом пула соединений и проверкой целостности (`PRAGMA integrity_check`).
4. **`AuthSettingsForm.cs`**:
   - Добавление кнопки и диалога подтверждения с выводом карточки восстанавливаемого бэкапа.
